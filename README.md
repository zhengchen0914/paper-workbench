# 论文工坊（Workbench）

本地网页工作台：把「读到一篇论文」变成「一篇可直接发布的公众号文章」。
中间过程自动跑，你只在**选题**和**终审**两处拍板。

当前版本 **M3**：论文库 → 选题池 → 解读 → 公众号文章 → 包装 → 终审 → 交付包。

---

## 启动

双击 `run.bat`，或：

```powershell
cd E:\论文工作台\workbench
.\run.ps1
```

打开 <http://127.0.0.1:8765>。

首次运行会自动建虚拟环境并装依赖（需要 `uv`）。之后启动约 1 秒。

---

## 三条入口、一条流水线

```
选题雷达 ─┐
arXiv     ├─▶ 选题池 ─▶ 解读 ─▶ 公众号正文 ─▶ 物料 ─▶ 终审 ─▶ 交付包
开源榜单 ─┘   【闸门1】  8 段格式  01–07 结构   标题/摘要  【闸门2】  zip/粘贴
GitHub        你勾选              自动          封面/标签   你过一遍

开源榜单 ──▶ 盘点文章（跳过解读环节，直接进终审）
```

### 状态机

| 对象 | 状态流转 |
|---|---|
| 候选 `candidates` | 待选题 → 已导入 / 已忽略（可恢复） |
| 榜单条目 `board_entries` | 每次刷新整表替换，并记录相对上次的 star 变化 |
| 解读 `kind=reading` | 待生成 → 排队中 → 生成中 → 已完成 / 失败 / 待 DSH 产出 |
| 文章 `kind=article` | 空 → 排队中 → 生成中 → 待终审 → 已通过（可撤回） |

作业队列是**单消费者串行**的：批量时一篇跑完自动接下一篇，不会因为并发撞上接口限速。

---

## 首次使用：七步

1. **设置** → 填接口地址、API Key、模型名 → 点「测试连接」；顺便确认雷达关键词。
2. **雷达** → 「抓取最新候选」→ 挑一篇「下载并建档」（也可跳过，直接用自己的 PDF）。
3. **榜单** → 选榜 → 「刷新」→ 需要写盘点时勾几项 → 「生成盘点文章」。
4. **论文库** → 「扫描『已完成』目录」或上传 PDF（也可「导入既有解读」）。
5. **选题池** → 勾几篇 → 「开始生产」。
6. 解读完成后开一篇 → 「生成公众号文章」。
7. **终审页** → 看标题候选/摘要/封面/违禁词/数字溯源 → 通过 → 下载交付包或打开粘贴页。

---

## 两种引擎

| 引擎 | 谁在干活 | 适合 |
|---|---|---|
| **内置模型** | 工作台直接调 OpenAI 兼容端点，流式回写 | 日常批量，一键跑完 |
| **交给 DSH** | 生成任务文件到 `data/dsh-tasks/`，你发进会话执行，产出后粘贴回来 | 要人工把控、或模型不支持长上下文 |

解读与改写两段都可独立选引擎。

## 已实现

### 资料层
- 扫描本地目录 / 上传 PDF / 导入既存 Markdown 解读
- 记录页数、字数、是否具备文本层；扫描件明确报错而不是静默失败
- 全文按页提取，超长按页码边界截断，并在提示词里声明未覆盖部分

### 选题雷达
- 按关键词走 arXiv 官方 Atom API 抓最新论文，请求间留 1 秒间隔
- 同一条目被多个关键词命中会自动合并，并记下命中的词
- **可解释打分（0–10）**：会议线索 +3 / 附开源 +2 / 标题命中关键词 +2 / 新鲜度 +3~1，
  每条加分都在卡片上写明理由，不是一个黑盒推荐分
- 一键「下载并建档」：抓 PDF、登记论文、建解读稿件，直接进入选题池与论文库

### 选题闸门
- 选题池把论文摊成卡片，勾选即进入生产队列
- 「开始生产」只处理已勾选且尚未完成的解读，批量排入串行队列

### 开源榜单
- 按 GitHub star 排序的领域榜，**榜单 = 一条可编辑的检索式**（权威性来自查询定义，不来自程序）
- 预置 5 个：AI 开源总榜 / 工业异常检测 / 缺陷检测·COD / Agent Skill 生态 / DSH 插件生态
- **两种视图**：
  - 总榜（存量）——当前 star 排名，附带相对上次刷新的变化
  - 涨星榜（增量）——按本周涨幅排序，靠 `board_history` 快照历史计算
- 每次刷新写入按日去重的快照；涨幅口径会明示：真实周涨幅 / 历史不足退化为「相对上次刷新」
- 导出 Markdown 表格；勾选项目可**直接生成盘点文章**
- **周资讯**：涨星榜 + 本周新论文 → 一篇周报（01 本周概览 / 02 开源动态 / 03 论文速递 / 04 值得跟进 / 05 下周关注）
- 限流说实话：未配 Token 时 10 次/分钟，配了 30 次/分钟；触发 403 会告诉你还有多少秒恢复

> 为什么不用"裸关键词搜索"：`anomaly detection in:name,description,readme` 会把任何 README
> 里提过该词的仓库都捞进来——实测搜「异常检测」第一名是 awesome-go。所以预置榜一律用
> `topic:` 或带引号的精确短语。

### 解读层
- 按工作区既有 8 段格式生成（`30 秒抓核心` → `附加增值`）
- 提示词含反幻觉硬约束：数字可溯源、未报告的写「论文未报告」、局限性要具体

### 质量核验（数字溯源）
- 生成稿里的每个数字逐个回查原始 PDF 文本，逐条列出「原文里找不到」的数字及上下文
- 归一化处理：百分号差异（`92.0%` vs 原文 `92.0`）、四舍五入（`49.4` vs 原文 `49.43`）
- 放在解读页与终审页上，人工复核有抓手，而不是只凭感觉

### 科研知识库
- 解读完成后**自动抽取创新点**，每个 `### N.` 模块对应一条，进「待确认」队列
- 每条含：一句话创新点 / 旧问题 / 核心机制 / 类型 / 适用场景 / 局限 / **原文依据**
- **机制用受控词表**（30 个）：词表不匹配时强制留空并提议新机制，**禁止挑最接近的凑数**
  ——把「主元素二值化」标成「小波变换」比留空更糟，会污染后续的机制聚合
- 模型新提议的机制标「待确认」，需人工点头才进正式词表
- **证据校验是确定性的**：每条引文回原文做逐字比对；对不上时标「模型改写」，
  并用字符级相似度（difflib）自动找回最接近的**原文原句**附在旁边——逼模型复述没用，
  实测它 6 条里 0 条逐字引用
- 待确认队列**按论文分组**：一次看一篇的 2–4 条，比翻几十张卡高效
- 按机制 / 类型 / 状态筛选 + 关键词搜索；详情页显示同机制的其他创新点

### 文章层
- 解读 → 公众号正文，**4 种结构模板**可选：深度拆解 / 速递速览 / 方法对比 / 复现教程
- 写作铁律内置（开头三句、每段 ≤5 行、不列功能清单、禁用行业黑话、结尾不给总结）
- 发布物料：5 个标题候选（带角度与点击分）、摘要、封面主副标题、话题标签
- 违禁词检查走**本地词表**（危险 / 慎用两级），结果确定可复核

### 排版层（5 套主题）
- **经典**：还原 mdnice 基线（16px 正文 / 26px 行高 / 细边框表格 / 蓝链）
- **微信绿**：h2 左侧绿条，最常见的公众号技术号风格
- **科技蓝**：深蓝标题、浅蓝引用底、深色代码块
- **纸感**：暖色纸底、衬线正文、砖红强调
- **极简黑白**：全灰阶，不抢内容
- 主题只写「标签 → 内联样式」，不碰 `position` / 伪元素 / class（这些会被微信编辑器过滤）；
  所有文字色都避开纯黑——mdnice 踩过的坑：纯黑 `color` 会被微信吞掉
- 终审页实时预览即导出效果，切换主题后粘贴页与交付包同步

### 配图层
- 从 PDF 抽取内嵌位图作为配图候选（跨页去重、过滤小图标）
- 大图自动缩到 1400px 宽并转 JPEG：某 18 页论文 34 张图从 44MB 降到 3.4MB
- 终审页图库，与正文图位数量对照

### 终审 + 交付
- 一页看完：标题候选、摘要卡、封面文案、标签、违禁词命中与上下文、配图、正文预览
- 通过 / 撤回 / 逐条换标题 / 单独重跑物料
- **粘贴页**：Markdown → 内联样式富文本，一键「复制正文（带格式）」直接粘进编辑器
- **交付包 zip**：`正文.md` + `正文.html` + `物料.json` + `图片/`
- 下载 Markdown 原件

## 实测记录（真实模型 / 真实网络，非模拟）

**选题雷达**（4 个关键词：surface defect detection / anomaly detection / camouflaged object detection / zero-shot anomaly segmentation）

| 环节 | 结果 |
|---|---|
| 抓取 | 35 篇候选 / 6.6 秒 |
| 打分分布 | 7 分 2 篇、6 分 1 篇、5 分 6 篇、4 分 6 篇，其余更低 |
| 下载建档 | 1 篇 / 2.5 秒 → 20 页 / 53,886 字，PDF 文本层正常 |
| 接续解读 | 6,936 字 / 40 秒，必需章节全命中，数字溯源 **33 / 33** |

**解读与改写**（以 `2407.12276v1.pdf`（VCP-CLIP，36 页 / 81,681 字）为样本）

| 环节 | 结果 |
|---|---|
| 解读生成 | 6,331 字 / 37 秒；12 个必需章节全部命中 |
| 解读数字溯源 | 65 / 66 个数字在原文找到 |
| 文章改写 | 4,008 字 / 33 秒；01–07 结构与摘要卡齐全 |
| 发布物料 | 5 个标题候选（含角度与点击分）+ 摘要 + 封面主副标题 + 4 个标签 |
| 文章数字溯源 | 25 / 25 全部命中 |
| 违禁词 | 命中「最佳」1 次（慎用级） |
| 配图 | 40 张 / 2.1 MB 交付包 |

**结构模板与字数**

用 `速递速览` 模板（目标 900–1300 字）连续生成 3 次，实际得到 2174 / 1988 / 2025 字。
加全局硬约束、加逐节字数上限都没有明显效果——**这个模型对篇幅指令不敏感**。
因此工作台不假装能控制字数，而是在终审页显示「超出目标 1300 字」徽章，把判断交回给人。

**开源榜单**

| 榜单 | 检索式 | 命中总数 | 头部结果 |
|---|---|---|---|
| AI 开源总榜 | `topic:ai stars:>3000` | 816 | openclaw ★392k、superpowers ★303k、hermes-agent |
| 工业异常检测 | `topic:anomaly-detection stars:>100` | 252 | cleanlab、sktime、pyod |
| 缺陷检测 / COD | `topic:defect-detection` | 505 | awesome-industrial-anomaly-detection ★3.8k、SINet、SINet-V2 |
| Agent Skill | `topic:agent-skills stars:>200` | 676 | anthropics/skills、addyosmani/agent-skills |
| DSH 插件 | `dsh in:name` | 49,142（噪声大，只看头部） | dsh-desktop、awesome-dsh-plugin、dsh-web |

5 个榜各刷新一次（未配 Token），耗时约 2–3 秒/榜，配额从 10 降到 4。
拿「缺陷检测」榜前 3 项生成盘点文章：**2,217 字 / 24 秒**，5 个章节齐全，数字与榜单一致。

**周资讯**

用「AI 开源总榜」前 5 个项目 + 本周 3 篇论文生成：**2,218 字 / 18 秒**，
01 本周概览 → 05 下周关注 五节齐全。

两个实际问题与处理：

1. **周涨幅第一天算不出来**。首次刷新只有当天快照，`weekly_baseline` 会退化为
   「相对上次刷新」并写在界面上；要真实周涨幅得积累 ≥7 天历史。界面不会假装有数据。
2. **模型会编日期**。第一版周报标题写成「2026.10.25」，而当天是 10.22。
   修正办法是把「本周区间 2026-10-15 ~ 2026-10-22 / 今天是 2026-10-22，日期不得虚构」
   显式写进提示词；重跑后文中出现的日期全部落在区间内。

## 设计取舍

- **单端口单进程**：没有前后端分离，没有构建步骤。打开即用。
- **HTMX 而非 SPA**：局部刷新够用，页面状态简单，改样式即时生效。
- **串行队列而非并发**：接口有速率限制，SQLite 也只有一个写者；「排队中」比「卡住」可预期。
- **不需要向量检索**：单篇精读把全文塞进上下文就够。
- **合规检查不交给模型**：词表比对是确定性的，结果可复核。
- **数据只落本地**：SQLite + 文件系统，除模型接口外无外部依赖。

## 已知限制

- 扫描件 PDF（无文本层）无法自动解读，会明确报错并建议改用 DSH 引擎。
- 配图只抽内嵌位图；矢量图与整页排版图不在此列。
- 违禁词表是常见子集，不是平台官方全量词库。
- **篇幅控制不可靠**：模型常超出目标字数 50% 以上，工作台只用徽章提示，不做强制裁剪。
- **榜单只看头部**：`dsh in:name` 这类查询命中总数噪声很大（4.9 万条），可信的是按 star 排的前几十条。
- **周涨幅要等**：`board_history` 只从本次版本开始积累，真实周环比需要至少 7 天的快照。
- **榜单不自动刷新**：目前手动点刷新；未配 GitHub Token 时只有 10 次/分钟，定时任务容易撞限流。
- **创新点抽取是模型判断**：数字能溯源，但「这个方法的机制是 X」无法机械核验，所以必须有待确认队列。
- **引文一律被改写**：实测模型 6 条证据里 0 条逐字引用，全靠自动回找原句兜底；相似度 <0.45 时不给原句。
- **知识库目前只到 P1**：能抽、能审、能筛；机制卡合并、跨论文演进链、写作时反哺还没做。
- 主题最终效果受公众号编辑器二次处理影响，个别样式（如深色代码块）可能被降级。
- 导出走「复制粘贴 / zip」，未接公众号草稿箱 API（需认证服务号与 IP 白名单）。
